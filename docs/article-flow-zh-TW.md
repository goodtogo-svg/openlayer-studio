# 文章與欄位串接重建

文章編輯稿應以一篇文章為一個 InDesign story，按實際欄位建立串接文字框。`pdf-rebuild` 的舊逐 span 途徑只適合作幾何／字型診斷，不應當作文章編輯稿交付。

```bash
ali article-rebuild source.pdf --out jobs/new-article-job \
  --font-map font-map.json --layout article-layout.json
```

新命令只準備素材、計畫與 JSX；Adobe 原生成功仍須執行、儲存並重新開啟驗證。

## 結構

- 長文：同一 article ID，依明確欄位順序串接 `nextTextFrame`，所有框共用同一 story。
- 段落：依原始縮排、字型／色彩與欄位連續性恢復；去除 PDF 自動換行，保留真正的段落標記。跨欄途中不強制結束段落。
- 小標：與後續兩行正文同欄，避免標題孤立於欄尾。
- 人物簡介：一個完整 story／文字框；遇照片繞排時使用單一具形狀的框，不逐行切框。
- 照片說明與表格：各說明或欄位獨立成框，不能把不同文章、不同記錄串成一個 story。
- 不支援字型符號的完整區域可明確保留原稿，不把缺字、丟失內容或半段原貌當成完整重建。

## Layout 格式

座標為 PDF points，rect 為 x0,y0,x1,y1；欄位順序即閱讀順序。

```json
{
  "schema": "ali-article-layout/1",
  "pages": [{
    "articles": [{
      "id": "article-a",
      "columns": [[20,150,180,700], [190,150,350,700]]
    }],
    "bios": [{"id":"profile-a", "rect":[400,150,600,350]}],
    "preserve_regions": []
  }]
}
```

每頁必須有一個規格（可空物件）；同一來源文字不能被不同文章重複認領。可以提供 source_sha256，防止誤套其他原稿。這次校刊使用經原稿視覺核對的明確區域，不宣稱是通用自動文章語意辨識。

font-map 延續 PDF 重建映射，另可提供本機 `file`，以字型渲染度量估算字寬；字型名稱與發行版本仍需審閱。

## 保留與驗證

移除原生文字使用狹窄字形帶、不填白、不變更圖片與向量；輸出前比對每頁保留文字的內容／字型 multiset。若任何保留區域改變，準備程序直接失敗。

原生驗證需包括：

1. 每篇文章的欄框共用同一 story，nextTextFrame 的連結順序正確。
2. story 內容與計畫完全一致，段落內沒有逐行硬換行。
3. 沒有溢排、缺字型或遺失連結。
4. 以未儲存副本縮短第一欄，下一欄起始文字會改變，而 story 全文不變；測試後丟棄變更。
5. PDF 外觀核對文章區域與欄位；重排可能改變換行與留白，不能宣稱像素級一致。

目前仍需人工審閱文章區域、閱讀順序、段落判斷與字型。表格目前是獨立可編輯欄位，尚非完整 InDesign 原生 table；特殊標題／照片仍可保留於連結向量底圖。
